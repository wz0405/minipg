# minipg 설계 문서

## 1. 파이프라인 개요

```
거래 발생 ──► 원장 적재 ──► 일정산 배치 ──► 거래대사 ──► 리포트
(실결제/시딩)   TR_MSTR      SM_STMT_TID      RC_RESULT     REST API
                            SM_STMT
```

| 단계 | 주체 | 시각(KST) | 내용 |
|---|---|---|---|
| 결제 | api | 상시 | 결제창/수기 승인·취소 → TR_MSTR INSERT |
| PG 자동취소 동기화 | batch | 23:30 | 데모 MID의 23시 전건 자동취소를 원장에 취소행으로 반영 |
| 일정산 | batch | 04:00 | 전일 거래 → 건별 수수료 → 가맹점별 집계 + 지급예정일 |
| 거래대사 | batch | 05:00 | 전일 원장 vs PG 거래내역 (TID, 상태) 키 대조 |

## 2. 아키텍처 — 결제 게이트웨이

```
Flutter / 가맹점(웹) 
   │ HTTP
   ▼
PaymentController (프로토콜 변환만)
   │ loopback TCP — 개행 구분 JSON 전문
   ▼
PayGateServer (Netty)
   ├─ 이벤트루프: 프레이밍(LineBasedFrameDecoder) + 디코딩까지만
   └─ PayGateHandler → 가상스레드 executor로 비즈니스 격리
                          │
                          ▼
                    PaymentService ──► NicepayClient (제휴사 통신)
                          │
                          ▼
                       TR_MSTR (INSERT-only)
```

설계 의도: 대외계 수신부(전문 게이트웨이)와 동일한 계층 구조.
이벤트루프에 DB 대기·제휴사 API 지연이 올라가면 게이트웨이 전체가 멈추므로,
블로킹 작업은 전부 전용 executor(가상스레드)로 내려보낸다.
HTTP는 어댑터일 뿐 결제의 단일 진입점은 게이트웨이 전문이다.

## 3. 테이블 사전

| 테이블 | 역할 | 핵심 규칙 |
|---|---|---|
| SI_MCHT | 가맹점 | SETTLE_CYCLE = 지급주기(N영업일) |
| SI_PTN_FEE | 원가 수수료 정책 | (가맹점, 수단, 적용일) 이력 관리 |
| SI_STMT_FEE | 판가 수수료 정책 | 〃 |
| TR_MSTR | 거래 원장 | **INSERT-only.** 취소 = 음수 금액 별도행(TX_ST_CD='2'), ORG_TID = 원거래 TID |
| SM_STMT_TID | 건별 정산 | 배치 시점 적용요율·계산결과 스냅샷 |
| SM_STMT | 일 정산 집계 | (정산일, 가맹점) PK, 지급예정일 포함 |
| IN_PG_TRX | PG 거래내역 수신 | 대사의 PG측 소스 (시딩 생성/AUTO_MOCK/파일) |
| RC_RESULT | 대사 불일치 | ONLY_US / ONLY_PG / AMT_MISMATCH |
| AD_HOLIDAY | 휴일 | 지급예정일 영업일 계산 |

## 4. 수수료 산식

```
수수료      = floor(|거래액| × 요율% / 100)     -- 원단위 절사
수수료 VAT  = floor(|판가수수료| × 10%)
마진        = 판가수수료 - 원가수수료
지급액      = 거래액 - 판가수수료 - VAT
지급예정일  = 거래일 + SETTLE_CYCLE 영업일 (주말·AD_HOLIDAY 이월)
```

- 취소행은 절대값으로 계산 후 부호 반전 — 음수에 절사를 직접 적용하면
  승인·취소 합이 0이 되지 않는 1원 오차가 생긴다.
- 수수료는 승인 시점이 아니라 **배치 시점에 계산**한다.
  정책 변경 후 재정산이 가능하고, 적용요율은 SM_STMT_TID에 스냅샷으로 남는다.
- 배치는 멱등: 같은 정산일 재실행 = DELETE 후 재생성.
- 정책 없는 가맹점 거래 발견 시 전체 롤백 (정산 마감은 all-or-nothing).

## 5. 거래대사

매칭 키: `(TID, TX_ST_CD)` — 승인과 취소를 각각 독립된 행으로 대조.

| 유형 | 의미 | 의심 원인 |
|---|---|---|
| ONLY_US | 내부에만 존재 | PG 미전송/유실 |
| ONLY_PG | PG에만 존재 | 내부 원장 적재 실패 |
| AMT_MISMATCH | 금액 불일치 | 변조/부분취소 미반영 |

시딩이 PG 소스를 함께 생성하며 `mismatchRate` 비율로 불일치를 의도 주입한다
— 대사가 실제로 잡아내는 모습을 시연하기 위함. PG 소스가 없는 날(실결제만 있던 날)은
AUTO_MOCK 미러를 만들어 대사가 성립하게 한다.

## 6. 결제수단 로드맵

| 단계 | 수단 | 방식 | 비고 |
|---|---|---|---|
| v1 (현재) | 카드 인증결제 | 나이스 결제창 JS SDK + 서버 승인 | 데모 MID, 23시 자동취소 |
| v1 (현재) | 카드 수기결제 | 키인(카드번호/유효기간/생년월일/비번2) | 카드 원본 비저장, 마스킹만 |
| v2 | 가상계좌 | 채번(발급) + 입금통보 웹훅 수신 | 입금대사 확장의 발판 |
| v2 | 정기결제(빌링) | 카드정보 → 빌키 발급 → 빌키 승인 | 샌드박스 지원 범위 확인 필요 |
| v3 | 선불 머니/포인트 | **자체 원장** — 회원 매체 잔액 충전/결제/취소 | PG 무관, 자체 구현 |
| 제외 | 실시간 계좌이체/휴대폰 | 샌드박스 실시간 승인 불가 | README 확장 포인트로만 명시 |

모든 수단은 TR_MSTR의 `PM_CD` 축으로 수렴하므로 정산·대사 파이프라인 수정 없이 추가된다.
수단별 수수료는 SI_PTN_FEE / SI_STMT_FEE의 PM_CD 행 추가로 대응한다.

## 7. 가맹점 연동 (호스티드 결제)

외부 시스템(예: 티켓 예매 시스템)은 minipg의 가맹점으로 연동한다:

```
가맹점 → GET /checkout.html?mchtId=...&amt=...&goodsNm=...&returnUrl=...
사용자 결제 완료 → returnUrl?rsltCd=0000&tid=...&amt=... 리다이렉트
가맹점: rsltCd 확인 후 주문 확정 (예매확정)
```

확장 예정: 결제요청 사전등록 API(금액 변조 방지), 서버 to 서버 결과통보(webhook) + 재통보,
통보 서명 검증. 티켓 시스템 연동 시 이 순서로 보강한다.

## 8. 시연 시나리오

1. **실결제 체험**: checkout.html에서 실카드 1,000원 승인 → 거래내역 확인 → 즉시 취소 or 23시 자동취소 대기
2. **취소 반영 정산**: 다음날 04시 배치 후 SM_STMT에서 해당 가맹점 정산금 0원(상쇄) 확인
3. **대량 정산**: 시딩(일 200건 × 30일, 취소 10%) → 배치 → 일정산/월 마진 리포트
4. **대사 검출**: 시딩 시 mismatchRate 2% → 대사 결과에서 ONLY_US/ONLY_PG/AMT_MISMATCH 검출 확인
5. **멱등 재실행**: 같은 정산일 배치 2회 실행 → 결과 동일 (DELETE-INSERT)

## 9. 배포 (시놀로지 NAS)

docker-compose 3컨테이너 (MariaDB + api + batch). JVM 힙은 NAS 램(2GB)에 맞춰
api 256m / batch 192m 제한. PG 키는 NAS 환경변수(.env)로만 주입.
